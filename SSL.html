项目部署——为域名安装 SSL 证书

作者：阿修  |  发布时间：2026-06-23  |  更新时间：2026-07-07

前言

在完成前面的操作后你会发现你的网页已经可以预览了

但是你会看到浏览器提示你的网页不安全

这是因为你没有为你的域名部署 SSL 证书导致的

这篇文章主要实现 SSL 证书的安装

分为两章 初创 ssl 证书 / 获取 ssl 证书 + 自动续约

一、实现

1. 安装 cerbot

运行以下指令（我的是 CentOS 系统）

# 1. 安装 Snap sudo yum install epel-release sudo yum install snapd # 2. 启用 Snap sudo systemctl enable --now snapd.socket sudo ln -s /var/lib/snapd/snap /snap # 3. 安装最新版 Certbot sudo snap install core sudo snap refresh core sudo snap install --classic certbot # 4. 创建软链接 相当于 Windows 中的快捷方式 后续想执行这个指令就不用每次都输入完整路径 直接输入 certbot 就可以 sudo ln -s /snap/bin/certbot /usr/bin/certbot

由于我的 nginx 是安装在 docker 容器里的

所以要先停掉 nginx 容器

docker stop

2. 获取并安装 SSL 证书

#获取并安装证书 #单域名：sudo certbot --nginx -d 域名 #多域名：sudo certbot --nginx -d 域名1 -d 域名2 #我这里使用多域名： sudo certbot certonly --standalone -d yun-mi-manchi.top -d admin.yun-mi-manchi.top --cert-name ssl

我这里是在宿主机中独立模式申请的证书

这里是将证书保存在系统默认路径的 /etc/letsencrypt/live/ssl/ 目录下 --cert-name 后面指定你要保存证书的文件夹名

二、关于 SSL 证书的自动续约

上面我们说了首次申请ssl证书

但是证书只有三个月有效期

我们要保证证书不能过期

所以要设置个自动程序来对证书进行续约

我们使用 webroot 的模式来对证书进行续约（standalone 模式会有端口占用问题 重新续约时还要停止服务 这样很不方便）

先找出你运行前端容器的配置文件

# 查看你的 Nginx 容器配置 docker exec <你的nginx容器名> cat /etc/nginx/conf.d/*.conf | grep -E "root|server_name"

先找到你前端项目存放的根目录

前台 yun-mi-manchi.top >>> /home/yun_blog_vue/blog/dist

后台 admin.yun-mi-manchi.top >>> /home/yun_blog_vue/admin/dist

在前面我们使用的是两个项目部署的证书是同一个

现在我们尝试两个项目分别部署不同的的证书

运行申请 ssl 证书的指令

sudo certbot certonly --webroot -d yun-mi-manchi.top sudo certbot certonly --webroot -d admin.yun-mi-manchi.top

这样证书就会被创建在默认路径下 /etc/letsencrypt/live/

然后找到证书的配置文件 /etc/letsencrypt/renewal/

修改两个配置文件

前台 yun-mi-manchi.top.conf

version = 5.6.0 archive_dir = /etc/letsencrypt/archive/yun-mi-manchi.top cert = /etc/letsencrypt/live/yun-mi-manchi.top/cert.pem privkey = /etc/letsencrypt/live/yun-mi-manchi.top/privkey.pem chain = /etc/letsencrypt/live/yun-mi-manchi.top/chain.pem fullchain = /etc/letsencrypt/live/yun-mi-manchi.top/fullchain.pem [renewalparams] account = 20 authenticator = webroot webroot_path = /home/yun_blog_vue/blog/dist, server = https://acme-v02.api.letsencrypt.org/directory key_type = ecdsa [[webroot_map]]

后台 admin.yun-mi-manchi.top.conf

version = 5.6.0 archive_dir = /etc/letsencrypt/archive/admin.yun-mi-manchi.top cert = /etc/letsencrypt/live/admin.yun-mi-manchi.top/cert.pem privkey = /etc/letsencrypt/live/admin.yun-mi-manchi.top/privkey.pem chain = /etc/letsencrypt/live/admin.yun-mi-manchi.top/chain.pem fullchain = /etc/letsencrypt/live/admin.yun-mi-manchi.top/fullchain.pem [renewalparams] account = 2 authenticator = webroot webroot_path = /home/yun_blog_vue/admin, server = https://acme-v02.api.letsencrypt.org/directory key_type = ecdsa [[webroot_map]]

上面这些配置好之后运行下面指令测试是否可以续约证书

且容器和宿主机项目的路径和证书的路径挂载正确

出现Congratulations代表续约流程配置正常。

四、让续约后自动重载Nginx

因为我们的 nginx 在 Docker 里的

所以要先找出前端工程的容器是哪个

docker ps

找到前端工程容器名称后测试Nginx配置是否合法

docker exec yun_blog_compose-yun_blog_vue-1 nginx -t

输出ok代表配置无错误：

nginx: the configuration file /etc/nginx/nginx.conf syntax is ok nginx: configuration file /etc/nginx/nginx.conf test is successful

手动测试重载命令

docker exec yun_blog_compose-yun_blog_vue-1 nginx -s reload

输出 signal process started 说明重载正常。

五、配置自动reload定时任务

使用 deploy-hook，仅在实际完成续约时才执行重载Nginx

sudo crontab -e

添加定时规则

0 3 * * * certbot renew --quiet --deploy-hook "docker exec yun_blog_compose-yun_blog_vue-1 nginx -s reload"

释义：每天凌晨3点检测证书有效期；仅续约成功时执行Nginx重载。

编辑器操作说明：

Vim：按i编辑，ESC后输入 :wq 保存退出

Nano：Ctrl+O保存，回车确认，Ctrl+X退出

强制续约完整测试命令

sudo certbot renew \ --force-renewal \ --deploy-hook "docker exec yun_blog_compose-yun_blog_vue-1 nginx -s reload"

执行后输入 echo $?，返回0代表全部流程执行成功。
